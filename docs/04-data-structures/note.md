# Часть 1. Тип данных и АТД

Мы различаем крепёж - винты, гайки и гвозди - по операциям, которые с ними выполняют: отверткой, гаечным ключом или молотком. С данными то же самое: **тип данных** определяется набором операций, которые с ним можно делать.

Строка допускает преобразование в верхний регистр и добавление символов. Логическое значение - операции `AND`, `OR`, `NOT`. Число - сложение, деление, вычитание. Тип данных - это не то, как данные выглядят, а то, что с ними можно делать.

## Абстракция

Абстракция прячет детали за простым интерфейсом. Автомобиль скрывает двигатель за панелью управления - водителю не нужно разбираться в машиностроении, чтобы повернуть руль.

В программировании то же самое. Одной строкой

```python
html = fetch_source("https://tusur.ru/ru")
```

мы получаем страницу сайта, хотя за этой строкой стоят разрешение доменного имени, создание сокета и установка зашифрованного соединения. Всё это спрятано за именем `fetch_source`.

## Абстрактный тип данных

**Абстрактный тип данных (АТД)** - это описание группы операций над данными определённого типа, без деталей того, как данные хранятся в памяти. АТД отвечает на вопрос "что можно делать", а не "как это устроено внутри".

Возьмём **стек**. Это коллекция, работающая по принципу **LIFO** (last in, first out) - последним пришёл, первым вышел, как стопка тарелок: кладёте сверху, сверху и берёте.

АТД стека - две операции:

- `push(e)` - положить элемент на вершину;
- `pop()` - снять элемент с вершины.

Больше со стеком ничего делать нельзя, и это не ограничение, а удобство: раз переменная - стек, мы всегда знаем, что элементы обрабатываются строго в порядке "последний первым". Стек - это то, что стоит за кнопкой "Отменить" в текстовом редакторе: каждая правка кладётся на вершину, отмена снимает последнюю.

![Стек: кладём и снимаем сверху](images/stack.svg#only-light)
![Стек: кладём и снимаем сверху](images/stack.dark.svg#only-dark)

**Очередь** - второй базовый АТД, работающий по принципу **FIFO** (first in, first out) - первым пришёл, первым вышел, как живая очередь в магазине. Операции: `enqueue(e)` (встать в конец) и `dequeue()` (выйти из начала).

![Очередь: первым пришёл, первым вышел](images/queue.svg#only-light)
![Очередь: первым пришёл, первым вышел](images/queue.dark.svg#only-dark)

Заметьте: нигде не сказано, *как именно* хранить элементы стека или очереди в памяти. Это и есть смысл АТД - интерфейс отделён от реализации. Один и тот же АТД можно реализовать по-разному, и сейчас мы это сделаем.

### 📝 Задача 1. Стек

> **Файл:** `stack.py` | **Класс:** `Stack`

Реализуйте стек. Методы:

- `is_empty()` - пуст ли стек;
- `push(item)` - положить элемент на вершину;
- `pop()` - снять и вернуть верхний элемент; если стек пуст, поднять `IndexError`;
- `peek()` - вернуть верхний элемент, не снимая его; если стек пуст, поднять `IndexError`;
- `size()` - количество элементов.

```python
s = Stack()
s.is_empty()       # True
s.push(1)
s.push(2)
s.push(3)
s.size()           # 3
s.peek()           # 3
s.pop()            # 3
s.pop()            # 2
s.is_empty()       # False
```

> **Проверьте себя:** что произойдёт при `pop()` из пустого стека в вашей реализации? Поднять `IndexError` - правильный выбор: это стандартное исключение Python для обращения по несуществующему индексу, и так делает встроенный список.

Реализуйте очередь. Методы:

- `is_empty()` - пуста ли очередь;
- `enqueue(item)` - добавить элемент в конец;
- `dequeue()` - убрать и вернуть элемент из начала; если очередь пуста, поднять `IndexError`;


# Часть 2. Массив и связный список

АТД описывает *что* можно делать, а **структура данных** - *как* данные лежат в памяти. Один и тот же АТД "список" можно реализовать двумя принципиально разными структурами, и выбор между ними решает всё.

## Массив

Массив - самый простой способ хранить набор элементов: единый непрерывный блок памяти, элементы записаны подряд. Если массив начинается с адреса $s$ и каждый элемент занимает $b$ байт, то $n$-й элемент лежит ровно по адресу $s + b \cdot n$.

Отсюда главное свойство массива - **мгновенный доступ по индексу** за $O(1)$: компьютер не ищет элемент, а вычисляет его адрес по формуле. Именно так устроен список `list` в Python.

У непрерывности есть цена. Вставка или удаление в середине требует сдвинуть все последующие элементы - это $O(n)$. А расширение массива упирается в то, что рядом может не оказаться свободного непрерывного куска памяти.

## Связный список

Связный список хранит элементы в отдельных ячейках, разбросанных по памяти. Каждая ячейка содержит значение и **указатель на следующую** ячейку; конец цепи помечен пустым указателем.

![Массив и связный список](images/array-linked.svg#only-light)
![Массив и связный список](images/array-linked.dark.svg#only-dark)

Связный список не требует непрерывной памяти и легко растёт: новая ячейка может жить где угодно, достаточно переставить указатели. Вставка и удаление в середине - за $O(1)$, если известен узел рядом.

Плата - доступ по индексу: чтобы добраться до $n$-й ячейки, надо пройти по цепочке от начала, это $O(n)$. И если известна только одна ячейка, назад не вернуться - указатель ведёт лишь вперёд. Такую проблему решает двусвязный список, где у каждой ячейки два указателя - вперёд и назад, - но это уже тема балльной задачи.

![Вставка в связный список](images/linked-list-insert.svg#only-light)
![Вставка в связный список](images/linked-list-insert.dark.svg#only-dark)

### 📝 Задача 3. Связный список

Реализуйте односвязный список. Узел `Node` хранит `data` и ссылку `next` (по умолчанию `None`). Класс `LinkedList`:

# Часть 3. Хеш-таблица

Словарь и множество в Python находят элемент за $O(1)$ - быстрее, чем любая структура на сравнении. Секрет - в **хеш-таблице**.

Идея проста. Заводим массив "кармашков" (buckets). Специальная **хеш-функция** превращает значение в номер кармашка, и элемент кладётся именно туда. Поиск - это снова вычислить хеш-функцию и заглянуть в один кармашек: сколько бы элементов ни было, шагов всегда одно и то же число.

![Хеш-таблица](images/hash-table.svg#only-light)
![Хеш-таблица](images/hash-table.dark.svg#only-dark)

У простой схемы есть подвох: два разных значения могут получить одинаковый номер кармашка. Это **коллизия**. Коллизии решают, например, связными списками: в одном кармашке лежит цепочка элементов с одинаковым хешем, и при поиске её проходят подряд.

Отсюда два правила хорошей хеш-таблицы:

1. **Хеш-функция разбрасывает значения равномерно** - тогда цепочки остаются короткими.
2. **Кармашков должно быть с запасом** - если таблица забита почти под завязку, коллизии случаются постоянно и поиск вырождается в $O(n)$.

Словарь и множество в Python устроены именно так. Вспомните из второго занятия: проверка `"слово" in big_set` мгновенна, а `"слово" in big_list` перебирает элементы по одному. Теперь понятно, почему: множество - это хеш-таблица.

### 📝 Задача 4. Множество на хеш-таблице

> **Файл:** `hash_set.py` | **Класс:** `HashSet`

Реализуйте множество на хеш-таблице с кармашками-списками. Методы:

- `__init__(size=10)` - создать `size` пустых кармашков;
- `_hash(value)` - номер кармашка для значения;
- `add(value)` - добавить значение, если его ещё нет;
- `remove(value)` - удалить значение, если оно есть;
- `contains(value)` - есть ли значение в множестве;
- `__len__` - количество элементов.

```python
s = HashSet()
s.add(1)
s.add(2)
s.add(2)          # повторно не добавляется
len(s)            # 2
s.contains(2)     # True
s.remove(1)
s.contains(1)     # False
```

Для чисел `_hash` можно сделать простым: `value % self.size`. Главное, что вы должны понять - почему поиск заканчивается за один шаг хеш-функции, а не за перебор.

> **Проверьте себя:** что произойдёт, если добавить значения `10` и `20` в таблицу размера 10? У них совпадёт номер кармашка - это коллизия. Убедитесь, что ваша реализация при коллизии не теряет ни одно из значений.

# Часть 4. Графы и деревья

До сих пор структуры выстраивали элементы в цепочку - один за другим. **Граф** - самая свободная из структур: это набор **вершин** и **рёбер**, соединяющих пары вершин, без всякого порядка и без ограничений на число соседей.

Графом описывают почти всё: людей в социальной сети (рёбра - дружба), города на карте (рёбра - дороги), страницы в интернете (рёбра - ссылки).

![Граф](images/graph.svg#only-light)
![Граф](images/graph.dark.svg#only-dark)

Граф хранят двумя способами. **Матрица смежности** - таблица $n \times n$, где в клетке $(i, j)$ стоит единица, если между вершинами $i$ и $j$ есть ребро. **Список смежности** - для каждой вершины список её соседей. Матрица проще для проверки "есть ли ребро между $i$ и $j$", но занимает $O(n^2)$ памяти; список компактнее и удобнее для обхода.

**Обход графа** - обойти все вершины, до которых можно добраться. Самый естественный обход - **поиск в ширину** (BFS): кладём стартовую вершину в очередь и дальше, снимая вершину, добавляем в очередь всех её ещё не посещённых соседей. Вершины выходят в порядке удаления от стартовой.

## Дерево - частный случай графа

**Дерево** - это граф без циклов, где у каждой вершины (кроме корня) ровно один родитель. Деревья удобны для иерархий: каталоги файлов, структура подчинения.

На этом месте логично было бы разобрать деревья поиска и кучи, но мы их отложим до раздела про деревья: там они получат полный разбор. Сейчас достаточно знать, что **двоичное дерево поиска** хранит в левом поддереве меньшие значения, в правом - большие, а **куча** мгновенно отдаёт минимальный элемент с вершины. Обе структуры - деревья со строгими правилами, и обе мы построим своими руками позже.

### 📝 Задача 5. Поиск в ширину

> **Файл:** `graph.py` | **Функция:** `bfs(graph, start)`

Напишите обход графа в ширину. Граф задан **списком смежности** - словарём, где ключ это вершина, а значение - список её соседей. Функция возвращает список вершин в том порядке, в котором их посещает BFS, начиная с `start`.

```python
graph = {
    1: [2, 3],
    2: [4],
    3: [4],
    4: [],
}
bfs(graph, 1)   # [1, 2, 3, 4]
```

Порядок соседей внутри одного уровня может отличаться в зависимости от того, как вы заводите очередь, - в примере выше сначала идёт 2, потом 3, потому что так они перечислены в списке соседей. Ваш порядок должен быть детерминированным: берите соседей в том порядке, в котором они лежат в списке.
