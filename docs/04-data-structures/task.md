## 1. Двусвязный список - ⭐ - 5 баллов



> **Файл:** `dll.py` | **Классы:** `Node`, `DoublyLinkedList`

В односвязном списке нельзя пройти назад: у ячейки только указатель на следующую. В **двусвязном** у каждой ячейки два указателя - `next` и `prev`. Реализуйте его.

Узел `Node` хранит `data`, `next` и `prev` (оба по умолчанию `None`). Класс `DoublyLinkedList`:

- `append(data)` - добавить узел в конец;
- `prepend(data)` - добавить узел в начало;
- `delete(data)` - удалить первое вхождение значения;
- `to_list()` - значения всех узлов от начала к концу;
- `to_list_reverse()` - значения от конца к началу.

```python
dll = DoublyLinkedList()
dll.append(1)
dll.append(2)
dll.append(3)
dll.prepend(0)
dll.to_list()           # [0, 1, 2, 3]
dll.to_list_reverse()   # [3, 2, 1, 0]
dll.delete(2)
dll.to_list()           # [0, 1, 3]
```

> **Проверьте себя:** в чём двусвязный список удобнее односвязного при удалении узла? Почему за это удобство приходится платить памятью?

## 2. Повторяющиеся символы - ⭐ - 5 баллов



> **Файл:** `count_duplicates.py` | **Функция:** `count_duplicates(text)`

Посчитайте, сколько **различных** символов встречается в строке больше одного раза. Регистр не учитывается, строка состоит из латинских букв и цифр.

```python

count_duplicates("aabbcde")           # 2    a и b
count_duplicates("aabBcde")           # 2    a и b, регистр не важен

```

## 5. Скобочная последовательность - ⭐⭐ - 10 баллов



> **Файл:** `brackets.py` | **Функция:** `is_balanced(s)`

Строка со скобками `()`, `[]` и `{}` называется **правильной**, если каждая открывающая скобка закрывается соответствующей, и скобки не перекрываются. Верните `True`, если строка правильная.

```python
is_balanced("()")              # True
is_balanced("([])")            # True
is_balanced("([{}])")          # True
is_balanced("(]")              # False
is_balanced("([)]")            # False
is_balanced("(")               # False
is_balanced("")                # True
```

Проверка в лоб (посчитать открывающие и закрывающие) не работает: `")("` и `"([)]"` имеют поровну тех и других, но неправильны. Нужен **стек**: открывающая скобка кладётся на вершину, а закрывающая должна совпасть с вершиной. Если закрывающая не совпала или в конце стек не пуст - строка неправильная.

## 7. Обратная польская запись - ⭐⭐⭐ - 15 баллов



> **Файл:** `rpn.py` | **Функция:** `evaluate_rpn(tokens)`

**Обратная польская запись** (ОПЗ) - способ записать выражение, где оператор стоит после операндов: `2 3 +` вместо `2 + 3`. Её ценность в том, что для вычисления не нужны скобки и приоритеты - достаточно стека.

Дан список `tokens`, в котором числа записаны как целые (`int`), а операторы - как строки `"+"`, `"-"`, `"*"`, `"/"`. Вычислите выражение и верните результат. Деление - обычное, с дробной частью.

```python
evaluate_rpn([2, 3, "+"])                # 5
evaluate_rpn([2, 3, "*"])                # 6
evaluate_rpn([5, 1, 2, "+", 4, "*", "+", 3, "-"])  # 14
evaluate_rpn([6, 2, "/"])                # 3.0
evaluate_rpn([4, 13, 5, "/", "+"])       # 6.6
```

Алгоритм: идёте по `tokens`, число кладёте в стек, оператор снимает со стека два операнда и кладёт обратно результат. Обратите внимание на порядок операндов для `-` и `/`: они снимаются в обратном порядке.

> **Проверьте себя:** зачем человечеству ОПЗ, если есть привычная инфиксная запись? Подсказка: посмотрите, насколько прост алгоритм, который вы только что написали, - и представьте, сколько усилий требует разбор приоритетов и скобок в обычном калькуляторе.

## 9. Кратчайший путь в графе - ⭐⭐⭐⭐ - 20 баллов



> **Файл:** `graph_path.py` | **Функция:** `shortest_path(graph, start, end)`

Дан невзвешенный граф в виде **списка смежности** (словарь: вершина - список соседей). Верните **кратчайший** путь от `start` до `end` как список вершин, включающий оба конца. Если пути нет, верните `None`.

```python
graph = {
    0: [1],
    1: [2, 3],
    2: [3],
    3: [],
}
shortest_path(graph, 0, 3)   # [0, 1, 3] --- через 2 было бы длиннее
shortest_path(graph, 3, 0)   # None --- из 3 никуда не добраться
```

Подсказка: в конспекте есть обход в ширину, который посещает вершины в порядке удаления от старта. Достаточно во время обхода **запоминать, откуда пришли** в каждую вершину, а в конце восстановить путь от `end` назад к `start`.

## 10. LRU-кэш - ⭐⭐⭐⭐⭐ - 25 баллов



> **Файл:** `lru.py` | **Класс:** `LRUCache`

**LRU-кэш** (least recently used) хранит не больше `capacity` пар "ключ - значение". Когда кэш полон и добавляется новый ключ, из него вытесняется тот, которым **не пользовались дольше всех**.

- `LRUCache(capacity)` - создать кэш;
- `get(key)` - вернуть значение по ключу или `-1`, если ключа нет; обращение к ключу обновляет его "свежесть";
- `put(key, value)` - добавить или обновить пару; при переполнении вытеснить наименее свежий ключ.

Обе операции должны работать за $O(1)$.

```python
cache = LRUCache(2)
cache.put(1, 1)
cache.put(2, 2)
cache.get(1)        # 1
cache.put(3, 3)     # вытесняется ключ 2 --- им не пользовались
cache.get(2)        # -1
cache.put(4, 4)     # вытесняется ключ 1
cache.get(1)        # -1
cache.get(3)        # 3
cache.get(4)        # 4
```

Наивное решение - хранить порядок в списке и двигать элемент в конец при каждом обращении - это $O(n)$ на операцию. Для проверки в тесте подаётся сотня тысяч операций, и такое решение не уложится во время. Понадобится сочетание из этого раздела: **словарь** для мгновенного доступа по ключу и **двусвязный список** для порядка свежести. Словарь указывает на узел списка, список позволяет вытащить узел и перенести его в конец за $O(1)$.
