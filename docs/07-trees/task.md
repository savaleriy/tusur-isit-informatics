## 1. Проверить, что дерево - BST - ⭐ - 5 баллов



> **Файл:** `is_bst.py` | **Функция:** `is_bst(root)`

Дано бинарное дерево (узлы с атрибутами `data`, `left`, `right`). Верните `True`, если оно является двоичным деревом поиска: **для каждого узла** всё в левом поддереве меньше его, всё в правом - больше.

```python
is_bst(Node(2, Node(1), Node(3)))          # True
is_bst(Node(5, Node(3), Node(7, Node(4), Node(9))))   # False
```

Второй пример - ловушка: у узла 7 левый потомок 4, что для самого узла 7 верно ($4 < 7$), но 4 лежит в **правом** поддереве корня 5, а значит должен быть больше 5. Проверка только соседних потомков эту ошибку пропустит.

> **Проверьте себя:** достаточно ли сравнить каждый узел только с его непосредственными потомками? Придумайте контрпример, как во втором случае выше.

## 3. Прыгающие числа - ⭐ - 5 баллов



> **Файл:** `jumping.py` | **Функция:** `is_jumping(n)`

Прыгающее число - это число, у которого модуль разности любых двух соседних цифр равен единице. Все однозначные числа считаются прыгающими.

```python
is_jumping(9)         # True    однозначное
is_jumping(23)        # True    |2-3| = 1
is_jumping(4343456)   # True
is_jumping(79)        # False   |7-9| = 2
```

> **Проверьте себя:** пройти по парам соседних символов строки удобно через `zip(s, s[1:])`. Разберитесь, почему это работает, - приём пригодится ещё много раз.

## 5. Удаление узла из BST - ⭐⭐ - 10 баллов



> **Файл:** `bst_delete.py` | **Функция:** `delete(root, key)`

Дан корень BST (узлы с атрибутами `data`, `left`, `right`) и ключ. Удалите узел с этим ключом и верните корень получившегося дерева. Если ключа нет - верните исходное дерево.

```python
#        5
#       / \
#      3   8
#     /   / \
#    2   7   9
root = Node(5, Node(3, Node(2)), Node(8, Node(7), Node(9)))

inorder(delete(root, 8))   # [2, 3, 5, 7, 9]  --- 8 заменился преемником 9
inorder(delete(root, 2))   # [3, 5, 7, 8, 9]  --- лист 2 просто убран
```

Три случая, которые надо разобрать: удаление листа; узла с одним потомком (потомок встаёт на его место); узла с двумя потомками (на место встаёт **преемник** - самый левый узел правого поддерева).

> **Проверьте себя:** почему преемник всегда имеет не больше одного потомка? Это делает случай "два потомка" сводимым к двум уже разобранным.

## 7. Самые частые элементы - ⭐⭐⭐ - 15 баллов



> **Файл:** `top_k.py` | **Функция:** `top_k_frequent(words, k)`

Дан список слов. Верните `k` слов, которые встречаются чаще всего, отсортированные по убыванию частоты. При равной частоте - в алфавитном порядке.

```python
words = ["apple", "banana", "apple", "cherry", "banana", "apple", "date"]
top_k_frequent(words, 2)   # ["apple", "banana"]
top_k_frequent(words, 3)   # ["apple", "banana", "cherry"]
```

Сначала посчитайте частоты словарём или `Counter`. Дальше нужна **куча**: положите в неё пары `(-частота, слово)` и снимите `k` элементов. Сортировать всё подряд не обязательно - куча позволяет достать только нужную верхушку.

> **Проверьте себя:** почему в кучу кладут отрицательную частоту? Что поменяется, если класть положительную?

## 8. Палиндромные пары - ⭐⭐⭐ - 15 баллов



> **Файл:** `palindrome_pairs.py` | **Функция:** `palindrome_pairs(words)`

Дан список различных слов. Найдите все пары индексов `(i, j)`, где `i != j`, такие что склейка `words[i] + words[j]` образует палиндром. Верните список пар, отсортированный по возрастанию: сначала по `i`, потом по `j`.

```python
palindrome_pairs(["bat", "tab", "cat"])
# [(0, 1), (1, 0)]

palindrome_pairs(["dog", "cow", "tap", "god", "pat"])
# [(0, 3), (2, 4), (3, 0), (4, 2)]

palindrome_pairs(["abcd", "dcba", "lls", "s", "sssll"])
# [(0, 1), (1, 0), (2, 4), (3, 2)]
```

> **Проверьте себя:** решение перебором пар имеет сложность $O(n^2 \cdot k)$, где $k$ - длина слова. Для списка слов из словаря этого мало. Подумайте, как помог бы словарь развёрнутых слов - это та же идея, что в задаче про анаграммы.

## 9. Кодирование и декодирование Хаффмана - ⭐⭐⭐⭐ - 20 баллов



> **Файл:** `huffman_codec.py` | **Функции:** `encode(text, codes)`, `decode(bits, codes)`

Дана таблица кодов Хаффмана `codes` - словарь "буква - код из нулей и единиц". Коды префиксные: ни один не является началом другого.

**`encode(text, codes)`** заменяет каждую букву её кодом и возвращает получившуюся битовую строку.

**`decode(bits, codes)`** выполняет обратную операцию: разбирает битовую строку на буквы по таблице кодов.

```python
codes = {"t": "0", "i": "10", "l": "11"}

encode("tilt", codes)        # "010110"
decode("010110", codes)      # "tilt"
```

Ключ к декодированию - обратный словарь: поменяйте в `codes` ключи и значения местами, затем идите по битам, накапливая код, пока он не совпадёт с ключом обратного словаря.

> **Проверьте себя:** почему для корректного декодирования важна именно префиксность? Что произойдёт, если один код будет началом другого?

## 10. Сбалансированное дерево из списка - ⭐⭐⭐⭐⭐ - 25 баллов



> **Файл:** `balanced_bst.py` | **Функция:** `build_balanced_bst(sorted_list)`

Дан **отсортированный по возрастанию** список чисел. Постройте из него BST минимальной высоты и верните корень (узлы с атрибутами `data`, `left`, `right`).

```python
root = build_balanced_bst([1, 2, 3, 4, 5, 6, 7])
# корень - 4, высота дерева 3
```

Наивный способ - вставлять элементы по одному в BST - даёт **вырожденное** дерево: каждый новый элемент уходит вправо, высота получается $n$, и поиск вырождается в $O(n)$. Проверка подаёт список из ста тысяч элементов, и такое решение либо не уложится во время, либо не пройдёт проверку высоты.

Правильный способ рекурсивен и работает за $O(n)$: возьмите средний элемент списка как корень, из левой половины постройте левое поддерево, из правой - правое. Средний элемент делит список пополам, поэтому высота получается $\log_2 n$.

> **Проверьте себя:** почему средний элемент - правильный выбор корня? Что было бы, если бы корнем каждый раз брали первый элемент?
