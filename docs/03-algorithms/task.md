## 1. Целый квадратный корень - ⭐ - 5 баллов



> **Файл:** `sqrt.py` | **Функция:** `integer_square_root(n)`

Верните наибольшее целое число `r`, такое что `r * r <= n`. Аргумент `n` неотрицательный.

```python
integer_square_root(0)       # 0
integer_square_root(4)       # 2
integer_square_root(8)       # 2
integer_square_root(10)      # 3
integer_square_root(100)     # 10
integer_square_root(10**12)  # 1000000
```

Наивный перебор `r = 1, 2, 3, ...` для больших `n` слишком медленный: корень из $10^{12}$ равен миллиону, столько шагов делать не хочется. Вспомните **бинарный поиск** из конспекта: искать можно не по массиву, а по ответу - границы `left` и `right`, каждый шаг отбрасывает половину диапазона.

## 2. Максимальный разрыв - ⭐ - 5 баллов



> **Файл:** `max_gap.py` | **Функция:** `max_gap(numbers)`

Максимальный разрыв - это наибольшая разность между соседними элементами списка **после сортировки** по возрастанию.

```python
max_gap([13, 10, 5, 2, 9])            # 4     после сортировки 2,5,9,10,13
max_gap([-3, -27, -4, -2])            # 23
max_gap([-54, 37, 0, 64, 640, 0, -15])  # 576
```

Если элементов меньше двух, верните 0.

> **Проверьте себя:** какова сложность вашего решения? Сортировка задаёт нижнюю границу - меньше $O(n \log n)$ этим способом не получится.

## 3. Уникальные подряд - ⭐ - 5 баллов



> **Файл:** `unique_in_order.py` | **Функция:** `unique_in_order(sequence)`

Уберите из последовательности идущие подряд повторы, сохранив порядок. Одинаковые элементы, стоящие не рядом, остаются оба. Верните список.

```python
unique_in_order("AAAABBBCCDAABBB")   # ['A','B','C','D','A','B']
unique_in_order("ABBCcAD")           # ['A','B','C','c','A','D']
unique_in_order([1, 2, 2, 3, 3])     # [1, 2, 3]
unique_in_order("")                  # []
```

> **Проверьте себя:** решение делается одним проходом и сравнением с предыдущим элементом, то есть за $O(n)$. Решение через `set` тут не годится - оно потеряет порядок и склеит далёкие повторы.

## 4. Сортировка по числу битов - ⭐ - 5 баллов



> **Файл:** `sort_by_bits.py` | **Функция:** `sort_by_bits(numbers)`

Отсортируйте список неотрицательных целых по возрастанию количества единичных битов в двоичной записи. Числа с одинаковым количеством битов идут по возрастанию своего значения.

```python
sort_by_bits([7, 6, 15, 8])             # [8, 6, 7, 15]
sort_by_bits([3, 8, 3, 6, 5, 7, 9, 1])  # [1, 8, 3, 3, 5, 6, 9, 7]
```

## 5. Пара с заданной суммой - ⭐⭐ - 10 баллов



> **Файл:** `two_sum.py` | **Функция:** `two_sum_sorted(arr, target)`

Дан **отсортированный по возрастанию** список чисел `arr` и число `target`. Верните пару `(a, b)`, такую что `a + b == target` и `a <= b`. Если такой пары нет, верните `None`. Если пар несколько, подойдёт любая.

```python
two_sum_sorted([1, 2, 3, 4, 5], 9)    # (4, 5)
two_sum_sorted([1, 2, 3, 4, 5], 10)   # None
two_sum_sorted([1, 3, 5, 7], 8)       # (3, 5) или (1, 7)
```

В лоб это два вложенных цикла - $O(n^2)$. Но список отсортирован, и это подсказка. Поставьте **два указателя**: один на начало списка, другой на конец. Если сумма больше нужной - сдвиньте правый указатель влево, если меньше - левый вправо. Так за один проход, $O(n)$.

> Проверьте свой ответ перебором на маленьком списке: расхождение означает ошибку в указателях.

## 6. Минимальная сумма произведений - ⭐⭐ - 10 баллов



> **Файл:** `min_pair_sum.py` | **Функция:** `min_pair_sum(numbers)`

Дан список положительных чисел чётной длины. Разбейте его на пары так, чтобы сумма попарных произведений была минимальной, и верните эту сумму. Каждый элемент используется ровно один раз.

```python
min_pair_sum([5, 4, 2, 3])              # 22    5*2 + 4*3
```

## 7. Анаграммы в словаре - ⭐⭐⭐ - 15 баллов



> **Файл:** `anagram_groups.py` | **Функция:** `largest_anagram_group(words)`

Дан список слов. Сгруппируйте их в анаграммы (напомним: анаграмма - слово, полученное перестановкой букв другого) и верните **самую большую группу** как отсортированный список слов. Если в списке нет ни одной пары анаграмм, верните пустой список. Если несколько групп одинаково велики, верните ту, чей отсортированный список слов меньше лексикографически.

Файл `data/words.csv` содержит около 58 тысяч английских слов, по одному в строке:

```python
with open("data/words.csv", encoding="utf-8") as f:
    words = f.read().splitlines()

largest_anagram_group(words)
# ['capers', 'escarp', 'pacers', 'parsec', 'recaps', 'scrape', 'spacer']
```

Ключевая идея: две анаграммы после сортировки букв дают **одинаковую** строку. Сделайте из отсортированных букв ключ словаря и соберите под каждым ключом все слова.

> **Проверьте себя:** сколько всего групп анаграмм (из двух и более слов) в файле? И есть ли среди них группа из одного слова? Подумайте, почему последний вопрос важен для функции, которая возвращает `[]`.

## 8. Индекс с равными суммами - ⭐⭐⭐ - 15 баллов



> **Файл:** `even_index.py` | **Функция:** `find_even_index(numbers)`

Найдите индекс `N`, при котором сумма элементов слева от него равна сумме элементов справа. Сам элемент с индексом `N` ни в одну сумму не входит. Если подходящих индексов несколько, верните наименьший; если такого нет, верните `-1`.

```python
find_even_index([1, 2, 3, 4, 3, 2, 1])       # 3    слева 1+2+3=6, справа 3+2+1=6
find_even_index([1, 100, 50, -51, 1, 1])     # 1    слева 1, справа 50-51+1+1=1
find_even_index([20, 10, -80, 10, 10, 15, 35])  # 0    слева пусто, справа 0
find_even_index([1, 2, 3, 4, 5, 6])          # -1
```

> **Проверьте себя:** решение в лоб считает обе суммы заново для каждого индекса, это $O(n^2)$. Существует решение за один проход: заведите две переменные и обновляйте их на каждом шаге. Тест на большом списке пропустит только второе.

## 9. Причудливые квадраты - ⭐⭐⭐⭐ - 20 баллов



> **Файл:** `quirky.py` | **Функция:** `quirky_numbers(k)`

У числа $3025$ есть замечательное свойство. Разрежем его запись пополам: $30$ и $25$. Сумма половин в квадрате даёт исходное число: $(30 + 25)^2 = 55^2 = 3025$.

Число с $2k$ цифрами назовём **причудливым**, если, разбив его на левую половину $L$ (первые $k$ цифр) и правую $R$ (последние $k$ цифр), мы получим $(L + R)^2 = N$. Ведущие нули учитываются: $0001$ - это $L = 00$, $R = 01$, и $(0 + 1)^2 = 1$.

Верните все причудливые числа с $2k$ цифрами, отсортированные по возрастанию, в виде строк с ведущими нулями.

```python
quirky_numbers(1)
# ['00', '01', '81']

quirky_numbers(2)
# ['0000', '0001', '2025', '3025', '9801']
```

Наивное решение перебирает все $10^{2k}$ чисел - при $k = 4$ это сто миллионов, медленно. Заметьте: $(L + R)^2 = N$ означает, что $N$ полностью определяется суммой $s = L + R$. Перебирать нужно не $N$, а $s$ - их всего $10^k$. Осталось научиться по $s$ восстанавливать $N$ и проверять, сходится ли разбиение.

> **Проверьте себя:** для $k = 3$ и $k = 4$ причудливые числа тоже есть, хотя интуиция подсказывает обратное. Найдите их все и убедитесь, что ваш алгоритм не полагается на "их, наверное, нет".

## 10. Число инверсий - ⭐⭐⭐⭐⭐ - 25 баллов



> **Файл:** `inversions.py` | **Функция:** `count_inversions(arr)`

**Инверсия** в списке - это пара позиций $i < j$, для которых `arr[i] > arr[j]`: два элемента стоят в "неправильном" порядке. Посчитайте число инверсий в списке.

```python
count_inversions([1, 2, 3])      # 0
count_inversions([3, 2, 1])      # 3
count_inversions([2, 4, 1, 3, 5]) # 3
count_inversions([5, 4, 3, 2, 1]) # 10
```

Решение в лоб - два вложенных цикла - даёт $O(n^2)$. На списке из $10^5$ элементов это $5 \cdot 10^9$ проверок, то есть десятки секунд, и автоматическая проверка этого не дождётся. Нужна идея посерьёзнее.

Подсказка: число инверсий можно считать **попутно со сортировкой слиянием**. Когда алгоритм слияния берёт элемент из правой половины, все ещё не взятые элементы левой половины больше его - значит, каждая такая ситуация добавляет к ответу их количество. Сортировка слиянием работает за $O(n \log n)$, и подсчёт инверсий не портит эту оценку.

> Сначала доведите до ума сортировку слиянием (она описана в конспекте), потом добавьте к ней счётчик. Сверьтесь перебором на маленьких списках.
