## `lambda` - функция без имени

Иногда функцию нужно передать куда-то один раз, и давать ей имя не хочется. Для этого есть `lambda`:

```python
def by_length(word):
    return len(word)

# то же самое одной строкой:
by_length = lambda word: len(word)
```

`lambda` пишется в одну строку и всегда возвращает значение: `lambda аргументы: результат`. Тело не может содержать ни `if`, ни циклов - только одно выражение.

Чаще всего `lambda` встречается как ключ сортировки.

## `sorted` с ключом

У функции `sorted` есть параметр `key`: это функция, которую применяют к каждому элементу, и сортируют по её результату.

```python
words = ["яблоко", "кот", "автобус", "дом"]

sorted(words)                       # по алфавиту: ['автобус', 'дом', 'кот', 'яблоко']
sorted(words, key=len)              # по длине:   ['кот', 'дом', 'яблоко', 'автобус']
sorted(words, key=len, reverse=True)  # наоборот
```

Сортировка **по последней цифре** - типичная задача, где без ключа не обойтись:

```python
sorted([91, 34, 15, 3, 42], key=lambda x: x % 10)
# [91, 42, 3, 34, 15]   - кончаются на 1, 2, 3, 4, 5
```

Сортировка по **кортежу** - это сортировка по нескольким критериям подряд:

```python
# сначала по последней цифре, при равенстве - по самому числу
sorted([91, 34, 15, 3, 42], key=lambda x: (x % 10, x))
# [91, 42, 3, 34, 15]
```

## Замер времени

Чтобы убедиться, что $O(n^2)$ действительно медленнее $O(n \log n)$, время надо **измерить**. Измеритель в стандартной библиотеке - `time.perf_counter`:

```python
import time

start = time.perf_counter()
# ... здесь код, который замеряем ...
elapsed = time.perf_counter() - start
```

`perf_counter` возвращает монотонный счётчик с наносекундной точностью - именно его нужно вычитать, а не часы на стене.

Сравним два способа отсортировать список из десяти тысяч случайных чисел:

```python
import random
import time

data = [random.randint(0, 10**6) for _ in range(10_000)]

start = time.perf_counter()
sorted(data)            # встроенная сортировка, O(n log n)
fast = time.perf_counter() - start
print(f"встроенная: {fast:.4f} c")

# наивная "сортировка" пузырьком заведомо медленнее
```

Замер всегда делают на большом объёме данных: на маленьком списке обе версии отработают мгновенно, и разница потеряется в шуме.

Для коротких фрагментов, которые надо прогнать много раз, есть модуль `timeit`:

```python
import timeit

timeit.timeit("sorted(data)", globals={"data": data}, number=100) / 100
```

`timeit` сам запускает код заданное число раз и усредняет время - так шум от других процессов сглаживается.

> **Замеряйте честно.** Не пишите `print(time.time())` дважды и не смотрите на секундомер. `time.perf_counter` создан именно для замера промежутков времени.

## Глубина рекурсии

Рекурсивные функции - те, что вызывают сами себя, - в Python по умолчанию могут вложиться не глубже тысячи вызовов:

```python
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)

factorial(1500)   # RecursionError: maximum recursion depth exceeded
```

Для задач, где рекурсия должна уходить глубже, ограничение поднимают:

```python
import sys
sys.setrecursionlimit(10000)
```

> **Поднимайте с оглядкой.** Глубокая рекурсия расходует память на каждый вызов. Если для решения нужно опускаться на миллионы уровней, рекурсия - не тот инструмент, нужен цикл.

Для сортировки миллиона элементов рекурсия, впрочем, не опасна: быстрая сортировка опускается лишь на $\log_2(10^6) \approx 20$ уровней - в пределах любого лимита.

## Типичные ошибки этого занятия

| Ошибка | Причина |
| - | - |
| `RecursionError` | рекурсия ушла глубже лимита - поднимите `sys.setrecursionlimit` или перепишите на цикл |
| функция "висит" секунды | оценили сложность? $O(2^n)$ и $O(n!)$ на больших $n$ не завершаются никогда |
| `sorted` не изменил список | `sorted` возвращает **новый** список - исходный не трогает |
| сортировка по первому элементу не сработала | нужен `key=`, иначе сортировка идёт по значению целиком |
| `lambda` не сработала | в `lambda` можно только одно выражение, никаких `if` и циклов |
