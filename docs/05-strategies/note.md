# Часть 1. Перебор в лоб

## Итерация

Итерация - самая простая стратегия: цикл `for` или `while` повторяет одни и те же действия над каждой порцией данных.

Классический пример - слить два отсортированных списка в один. Два указателя идут по спискам, и на каждом шаге меньший из двух текущих элементов уходит в результат:

```text
функция merge(левый, правый):
    результат <- пустой список
    пока оба списка не пусты:
        если левый[0] <= правый[0]:
            переложить левый[0] в результат
        иначе:
            переложить правый[0] в результат
    дописать остаток непустого списка
    вернуть результат
```

Каждый элемент перекладывается ровно один раз, поэтому сложность - $O(n)$. Этот же `merge` вы уже видели в разделе про алгоритмы - здесь он нужен как пример чистой итерации.

## Рекурсия

Рекурсия - когда функция вызывает саму себя. Она естественно подходит для задач, которые формулируются через самих себя.

Числа Фибоначчи: $F(0) = 0$, $F(1) = 1$, а дальше каждое - сумма двух предыдущих. Определение буквально просит рекурсию:

```text
функция fib(n):
    если n <= 1:
        вернуть n
    вернуть fib(n-1) + fib(n-2)
```

Рекурсия короче итеративного решения, но у неё есть цена. Функция `fib(5)` вызывает `fib(4)` и `fib(3)`, а `fib(4)` снова вызывает `fib(3)` - одни и те же значения считаются многократно. Дерево вызовов растёт как $2^n$.

![Дерево вызовов fib(5)](images/fib-tree.svg#only-light)
![Дерево вызовов fib(5)](images/fib-tree.dark.svg#only-dark)

На рисунке видно, сколько раз повторяется `fib(2)` и `fib(3)`. Наивная рекурсия для Фибоначчи имеет сложность $O(2^n)$: добавили единицу к $n$ - и время удвоилось. К этой проблеме мы вернёмся, когда дойдём до динамического программирования.

## Полный перебор

Полный перебор (brute force) - стратегия "проверим все варианты". Она не хитроумна, но надёжна: если перебрать все возможные решения, лучшее точно не пропустишь.

Вернёмся к рюкзаку. Даны предметы, у каждого вес и стоимость, и вместимость рюкзака. Нужно выбрать подмножество предметов с максимальной стоимостью, не превысив вес.

У $n$ предметов $2^n$ подмножеств. Идея полного перебора: сгенерировать их все и выбрать лучшее из тех, что влезают.

```text
функция knapsack_bruteforce(предметы, вместимость):
    лучшая <- 0
    для каждого подмножества предметов:
        если суммарный вес <= вместимость и суммарная стоимость > лучшая:
            лучшая <- суммарная стоимость
    вернуть лучшую
```

Для каждого из $2^n$ подмножеств выполняется постоянное число операций, поэтому сложность - $O(2^n)$. Для 30 предметов это уже миллиард подмножеств. Полный перебор честно работает на маленьких данных и честно тонет на больших - и в этом его главная ценность: он даёт точку отсчёта, от которой мы будем отталкиваться.

```python

```

Как перебрать все подмножества? Вспомните степенное множество из этого раздела: каждый предмет либо берём, либо нет, а рекурсия по предметам перебирает обе возможности.

# Часть 2. Жадность и возврат

## Жадные алгоритмы

Жадный алгоритм на каждом шаге делает лучший с виду выбор и **никогда не откатывается**. Быстро, но без гарантии оптимальности.

Жадный грабитель собирает рюкзак так: берёт самые дорогие предметы, пока они влезают.

```text
функция greedy_knapsack(предметы, вместимость):
    отсортировать предметы по убыванию стоимости
    вес_в_рюкзаке <- 0
    для каждого предмета в отсортированном списке:
        если вес_в_рюкзаке + вес_предмета <= вместимость:
            положить предмет
    вернуть суммарную стоимость
```

Жадность не всегда оптимальна. Возьмите предметы `(вес 6, стоимость 10)`, `(вес 5, стоимость 9)` и `(вес 5, стоимость 8)` при вместимости 10. Жадный схватит самый дорогой предмет весом 6 - и на этом остановится, получив 10, хотя два дешёвых вместе дают 17 и ровно влезают. Жадность видит только текущий шаг.

Но иногда жадность даёт точный ответ. Задача о проводах: соединить все посёлки в сеть с минимумом проводов. Жадное правило - каждый раз тянуть провод к ближайшему ещё не подключённому посёлку - строит **минимальное остовное дерево** и всегда оптимально.

![Минимальное остовное дерево](images/mst.svg#only-light)
![Минимальное остовное дерево](images/mst.dark.svg#only-dark)

Отсюда главный вопрос про жадность: как понять, подходит ли задача для неё? Есть задачи, где жадность доказуемо оптимальна, и есть те, где она ошибается. Если сомневаетесь - проверьте жадный ответ полным перебором на маленьких данных.

## Поиск с возвратом

Жадный алгоритм не откатывается, полный перебор - перебирает всё. Между ними - **поиск с возвратом** (backtracking): строим решение шаг за шагом, и как только понимаем, что текущий путь никуда не ведёт, **отменяем последний шаг** и пробуем другой вариант.

Разница с полным перебором в том, что бесперспективные пути обрезаются, не достраиваясь до конца. Возврат - это способ обойти дерево вариантов, не заходя в тупики.

Классический пример - **расставить $n$ ферзей** на доске $n \times n$ так, чтобы ни один не бил другого. Ставим ферзя в первую строку, переходим ко второй, ищем свободную клетку; если во всей строке клеток нет - возвращаемся и переставляем ферзя из первой строки.

```text
функция n_queens(n):
    решения <- 0
    функция расставить(строка):
        если строка == n:
            решения <- решения + 1
            вернуть
        для каждой колонки:
            если ферзя можно поставить в (строка, колонка):
                поставить ферзя
                расставить(строка + 1)
                убрать ферзя           # <- шаг возврата
    расставить(0)
    вернуть решения
```

Ключевая строка - "убрать ферзя": откатив ход, мы пробуем следующую колонку. Без этого шага это была бы не стратегия, а угадывание.

![Одно из решений для 4 ферзей](images/n-queens.svg#only-light)
![Одно из решений для 4 ферзей](images/n-queens.dark.svg#only-dark)

# Часть 3. Разделяй и властвуй и динамическое программирование

## Разделяй и властвуй

Разделяй и властвуй делит задачу на независимые подзадачи, решает их рекурсивно и объединяет ответы. Вы уже видели эту стратегию: сортировка слиянием делит список пополам, сортирует половины и сливает их. Каждый уровень деления обрабатывает $n$ элементов, уровней $\log_2 n$ - итого $O(n \log n)$.

Задачу о рюкзаке тоже можно разделить. Рассмотрим последний предмет: он либо взят, либо нет. Оптимальное решение - лучший из двух вариантов:

$$K(i, c) = \max\big(K(i-1, c),\ K(i-1, c - w_i) + v_i\big)$$

Здесь $K(i, c)$ - максимальная стоимость, которую дают первые $i$ предметов при вместимости $c$. Либо мы не берём $i$-й предмет и остаёмся с $K(i-1, c)$, либо берём - и остаётся $K(i-1, c - w_i)$ плюс его стоимость.

## Динамическое программирование

Рекурсивное деление из прошлого абзаца имеет проблему: одни и те же подзадачи считаются много раз. **Динамическое программирование** замечает это и запоминает результаты, чтобы каждый считать однажды.

Вернёмся к Фибоначчи. Наивная рекурсия вычисляет `fib(3)` десятки раз. Сохраним результаты в словаре и будем считать `fib(k)` только если его там ещё нет:

```text
память <- {0: 0, 1: 1}
функция fib(n):
    если n нет в памяти:
        память[n] <- fib(n-1) + fib(n-2)
    вернуть память[n]
```

Этот приём называется **мемоизацией**, и он превращает $O(2^n)$ в $O(n)$. Тот же приём решает рюкзак: заполняем таблицу $K(i, c)$ по формуле выше, и каждая ячейка считается один раз.

![Таблица динамического программирования для рюкзака](images/knapsack-dp.svg#only-light)
![Таблица динамического программирования для рюкзака](images/knapsack-dp.dark.svg#only-dark)

Разделяй и властвуй и динамическое программирование родственны, но отличаются одним: подзадачи первого **независимы**, подзадачи второго **перекрываются**. Когда вычисления повторяются - мемоизируйте.

# Часть 4. Ветви и границы

Последняя стратегия - для задач оптимизации: найти самый дешёвый маршрут, самую большую прибыль. **Ветви и границы** выигрывают время, отбрасывая заведомо плохие варианты ещё до их полного рассмотрения.

## Верхние и нижние границы

Идея опирается на два понятия. **Нижняя граница** - значение, про которое мы знаем, что решение не хуже: любой найденный ответ задаёт её. **Верхняя граница** - оптимистичная оценка, про которую мы знаем, что решение не лучше.

Для рюкзака нижнюю границу даёт жадный алгоритм (он всегда что-то находит), а верхнюю - "рассыпчатая" версия задачи, где предметы можно сыпать как крупу: бери самое выгодное по соотношению цена/вес, пока есть место. Сыпучий рюкзак заведомо не хуже настоящего, где предметы неделимы, - значит, он задаёт верхнюю границу.

## Отсечение

Строим дерево вариантов: у каждого узла - принятые решения, нижняя и верхняя границы. Если верхняя граница ветви **хуже** уже найденного решения, ветвь отбрасываем целиком: какой бы хорошей она ни оказалась, лучше текущего ответа ей не быть.

```text
лучший <- -бесконечность
поместить корень в очередь
пока очередь не пуста:
    узел <- взять самый перспективный из очереди
    если верхняя_граница(узел) <= лучший:
        отбросить узел
    если узел --- полное решение:
        лучший <- максимум(лучший, стоимость(узел))
    иначе:
        для каждого варианта следующего шага:
            добавить дочерний узел в очередь
```

Это и есть метод ветвей и границ: ветвимся по вариантам и ограничиваем поиск границами. На задаче о рюкзаке он находит оптимум, проверив лишь малую часть из $2^n$ подмножеств.

Классическая жертва этой стратегии - задача коммивояжёра: объехать $n$ городов и вернуться, потратив минимум топлива. Полный перебор маршрутов - $O(n!)$, но нижняя граница (расстояние по прямой уже не короче любого маршрута) позволяет отсекать ветви и решать задачу для десятков городов там, где перебор безнадёжен.

Ветви и границы - самая сложная из восьми стратегий, и её стоит вспоминать именно тогда, когда простые стратегии уже не справляются. До тех пор хватает перебора, жадности, возврата и динамического программирования.
