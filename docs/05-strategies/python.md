## Мемоизация через `lru_cache`

Наивная рекурсия для Фибоначчи вычисляет одни и те же значения многократно. Вместо того чтобы писать словарь-память вручную, можно повесить готовый декоратор:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

fib(500)   # работает мгновенно, хотя без кеша это O(2^n)
```

`@lru_cache` запоминает результаты вызовов: если функция уже вызывалась с тем же аргументом, она просто возвращает сохранённый ответ, не пересчитывая. `maxsize=None` означает "помнить всё".

Одна строка-декоратор заменяет ручной словарь и делает рекурсивную функцию линейной. Это самый быстрый способ написать мемоизацию.

## Генераторы и `yield`

Полный перебор всех подмножеств или перестановок порождает $2^n$ или $n!$ элементов. Если хранить их все в списке, память кончится раньше, чем ответ посчитается. Генератор выдаёт элементы **по одному**, по мере запроса:

```python
def subsets(items):
    if not items:
        yield ()
        return
    first, *rest = items
    for subset in subsets(rest):
        yield subset                  # не берём первый элемент
        yield (first,) + subset       # берём первый элемент

for s in subsets([1, 2, 3]):
    print(s)      # элементы появляются по одному, не все сразу
```

Ключевое слово `yield` делает из функции генератор: она не выполняет всё разом, а приостанавливается на каждом `yield` и продолжает, когда у неё попросят следующий элемент. Никакого списка на $2^n$ кортежей в памяти - только текущий.

Генератор годится всюду, где нужен перебор без материализации: искать лучшее подмножество, не храня их все.

## Глубина рекурсии

Рекурсия в Python по умолчанию ограничена примерно тысячей вложенных вызовов. Когда задача уходит глубже - например, обход дерева высотой в десятки тысяч, - ограничение поднимают:

```python
import sys
sys.setrecursionlimit(10000)
```

Но помните: глубокая рекурсия ест память на каждый вызов. Если нужно опуститься на миллионы уровней, перепишите на цикл - рекурсия тут не тот инструмент.

## `itertools`: напоминание

Перебор вариантов удобно делать готовыми функциями из `itertools`, которые мы видели во втором занятии:

```python
from itertools import product, permutations, combinations

product([0, 1], repeat=3)          # все 2^3 = 8 двоичных наборов
permutations("ABC")                # все 6 перестановок
combinations("ABCD", 2)            # все сочетания по 2
```

`product([0, 1], repeat=n)` - это и есть все подмножества из $n$ элементов: единица на позиции означает "элемент взят". Эти итераторы, как и генераторы, не создают результат целиком - они ленивы.

## Типичные ошибки этого занятия

| Ошибка | Причина |
| - | - |
| `RecursionError` | рекурсия ушла глубже лимита - поднимите `sys.setrecursionlimit` или перепишите на цикл |
| перебор "завис" | оценили сложность? $O(2^n)$ и $O(n!)$ на больших $n$ не завершаются никогда |
| `lru_cache` не сработал | аргументы должны быть хешируемыми - список в аргумент кешировать нельзя |
| генератор выдал пустоту | генератор выполняется лениво - без `for` или `list()` он ничего не сделает |
| жадный ответ не совпал с оптимальным | жадность не гарантирует оптимум - сверяйтесь с перебором на маленьких данных |
