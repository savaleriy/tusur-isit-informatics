## 1. Лучшая сделка - ⭐ - 5 баллов



> **Файл:** `best_deal.py` | **Функция:** `best_deal(prices)`

Дан список цен на золото по дням. Найдите максимальную прибыль от покупки в один день и продажи в другой, более поздний. Если прибыль получить невозможно, верните `0`.

```python
best_deal([7, 1, 5, 3, 6, 4])   # 5    --- купить за 1, продать за 6
best_deal([7, 6, 4, 3, 1])      # 0    --- цены только падают
best_deal([1, 2, 3, 4, 5])      # 4
```

Проще всего - полный перебор всех пар дней, это $O(n^2)$. Подумайте, нельзя ли быстрее: идя по дням, помните минимальную цену, встреченную раньше, - тогда прибыль при продаже в текущий день считается мгновенно.

> **Проверьте себя:** почему недостаточно найти просто минимум и максимум во всём списке? Придумайте пример, где минимум стоит после максимума.

## 2. Двойной факториал - ⭐ - 5 баллов



> **Файл:** `double_factorial.py` | **Функция:** `double_factorial(n)`

Двойной факториал - это произведение чисел одной чётности с `n`, не превосходящих `n`:

$$n!! = n \cdot (n-2) \cdot (n-4) \cdot \ldots$$

Произведение доходит до 1 для нечётного `n` и до 2 для чётного. По определению $0!! = 1$.

```python
double_factorial(5)   # 15    5 * 3 * 1
double_factorial(8)   # 384   8 * 6 * 4 * 2
double_factorial(0)   # 1
double_factorial(1)   # 1
```

> **Проверьте себя:** запишите решение и циклом, и рекурсией. Рекурсивное определение читается почти как формула: $n!! = n \cdot (n-2)!!$.

## 4. Проверка маршрута - ⭐ - 5 баллов



> **Файл:** `walk.py` | **Функция:** `is_valid_walk(walk)`

Прогулка по городу с идеальной сеткой улиц задана списком шагов из символов `'n'`, `'s'`, `'e'`, `'w'`. Каждый шаг занимает одну минуту. Верните `True`, если прогулка длится **ровно 10 минут** и заканчивается там же, где началась.

```python
is_valid_walk(['n','s','n','s','n','s','n','s','n','s'])           # True
is_valid_walk(['w','e','w','e','w','e','w','e','w','e','w','e'])   # False   двенадцать шагов
is_valid_walk(['w'])                                                # False
is_valid_walk(['n','n','n','s','n','s','n','s','n','s'])           # False   не вернулись
```

> **Проверьте себя:** проверку длины стоит делать первой - она стоит одну операцию и отсекает большинство неподходящих маршрутов, не считая координат.

## 5. Степенное множество - ⭐⭐ - 10 баллов



> **Файл:** `power_set.py` | **Функция:** `power_set(items)`

Верните **все подмножества** переданного списка. Каждое подмножество - кортеж, сами подмножества можно вернуть в любом порядке.

```python
sorted(power_set([1, 2, 3]), key=lambda s: (len(s), s))
# [(), (1,), (2,), (3,), (1, 2), (1, 3), (2, 3), (1, 2, 3)]
```

У списка из $n$ элементов ровно $2^n$ подмножеств. Постройте их итеративно, как в конспекте: начиная с пустого множества, для каждого нового элемента удваивайте уже имеющиеся подмножества - одно без элемента, другое с ним.

> **Проверьте себя:** почему подмножеств ровно $2^n$? Свяжите это с двоичными строками длины $n$: единица на позиции означает "элемент взят".

## 6. Пентобоначчи - ⭐⭐ - 10 баллов



> **Файл:** `pentafib.py` | **Функция:** `count_odd_pentafib(n)`

Последовательность Пентобоначчи начинается с $0, 1, 1, 2, 4$, а каждый следующий член равен сумме **пяти** предыдущих.

Верните количество **различных нечётных** значений среди членов с нулевого по `n`-й включительно. Число 1 встречается дважды и учитывается один раз.

> **Проверьте себя:** наивная рекурсия здесь делает пять вызовов вместо двух и тонет ещё быстрее, чем у Фибоначчи. Считайте итеративно или примените мемоизацию из этого занятия.

## 7. Минимум монет - ⭐⭐⭐ - 15 баллов



> **Файл:** `coin_change.py` | **Функция:** `coin_change(coins, amount)`

Даны номиналы монет `coins` и сумма `amount`. Верните **минимальное** число монет, которым можно набрать сумму, или `-1`, если это невозможно. Монет каждого номинала бесконечно много.

```python
coin_change([1, 2, 5], 11)      # 3    --- 5 + 5 + 1
coin_change([1, 3, 4], 6)       # 2    --- 3 + 3

coin_change([1], 0)             # 0
```

Второй пример - ловушка для жадности: жадный алгоритм возьмёт 4, потом две единицы (три монеты), но оптимально две тройки. Жадность здесь не работает, нужна таблица динамического программирования: `dp[a]` - минимальное число монет для суммы `a`.

> **Проверьте себя:** придумайте набор номиналов, где жадный алгоритм ошибается, и убедитесь, что ваше решение даёт правильный ответ.

## 9. Наибольшая возрастающая подпоследовательность - ⭐⭐⭐⭐ - 20 баллов



> **Файл:** `lis.py` | **Функция:** `longest_increasing_subsequence(nums)`

Верните **длину** самой длинной строго возрастающей подпоследовательности - последовательности элементов, идущих в том же порядке, что в исходном списке, но не обязательно подряд.

```python
longest_increasing_subsequence([10, 9, 2, 5, 3, 7, 101, 18])  # 4
longest_increasing_subsequence([0, 1, 0, 3, 2, 3])            # 4
longest_increasing_subsequence([7, 7, 7, 7])                  # 1
longest_increasing_subsequence([])                            # 0
```

В первом примере подпоследовательность - `[2, 3, 7, 101]` или `[2, 5, 7, 101]`, длина 4. Классическое решение - динамическое программирование: `dp[i]` это длина наибольшей возрастающей подпоследовательности, заканчивающейся в элементе `i`, и считается она через все предыдущие меньшие элементы.

> **Проверьте себя:** почему для `[7, 7, 7, 7]` ответ 1, а не 4? Вспомните, что значит "строго" возрастающая.

## 10. Число путей в сетке - ⭐⭐⭐⭐⭐ - 25 баллов



> **Файл:** `grid_paths.py` | **Функция:** `grid_paths(rows, cols)`

Дана сетка `rows` на `cols`. Вы стартуете в левом верхнем углу и можете шагать только **вниз** или **вправо**. Верните число способов добраться до правого нижнего угла.

```python
grid_paths(3, 3)   # 6
grid_paths(2, 7)   # 7
```

Наивное решение - рекурсия, пробующая оба шага из каждой клетки. Но каждый шаг удваивает число путей, и для сетки $30 \times 30$ это $2^{58}$ вызовов - не завершится никогда. Проверка подаёт такие размеры.

Правильный способ - динамическое программирование: заведите таблицу `dp`, где `dp[i][j]` - число путей в клетку `(i, j)`. В клетку можно прийти сверху или слева, поэтому `dp[i][j] = dp[i-1][j] + dp[i][j-1]`. Первая строка и первый столбец заполняются единицами.

> **Проверьте себя:** сравните результат для $3 \times 3$ с сочетанием из второго занятия. Число путей в сетке - это число способов выбрать, какие шаги будут вниз, то есть $\binom{rows+cols-2}{rows-1}$. Совпало?
