## 1. Азбука Морзе - ⭐ - 5 баллов



> **Файл:** `morse_code.py` | **Функции:** `to_morse(text)`, `from_morse(code)`

Словарь кодов лежит в `data/morse.py`. Импортируйте его, а не переписывайте руками:

```python
from morse import morse

morse["A"]    # '.-'
```

**Формат записи:** буквы внутри слова разделяются **пробелом**, слова - символом слеш с пробелами по краям.

**`to_morse(text)`** переводит текст в код. На вход подаются заглавные латинские буквы, цифры и пробелы.

**`from_morse(code)`** переводит обратно.

```python
to_morse("PYTHON 3")
# '.--. -.-- - .... --- -. / ...--'

to_morse("SOS")
# '... --- ...'

from_morse('.--. -.-- - .... --- -. / ...--')
# 'PYTHON 3'

from_morse('... --- ...')
# 'SOS'
```

Для обратного перевода понадобится словарь, в котором ключи и значения поменяны местами. Как получить его одной строкой - написано в [Python-конспекте](python.md).

Проверьте себя: для любого корректного текста должно выполняться

```python
from_morse(to_morse(text)) == text
```

> **Почему это работает.** Азбука Морзе не является префиксным кодом: код буквы E это точка, и с точки начинаются коды ещё десятка букв. Именно поэтому разделители обязательны - без пробелов строку `...` можно прочитать и как S, и как EEE, и как IE, и как EI. Настоящие префиксные коды, которые разделителей не требуют, мы построим в разделе про деревья.

## 5. Тетрация - ⭐⭐ - 10 баллов



> **Файл:** `tetration.py` | **Функция:** `tetration(x, n)`

**Тетрация** - это следующий гипероператор после возведения в степень. Смотрите на закономерность:

- умножение это повторённое сложение: $x \cdot n = \underbrace{x + x + \ldots + x}_{n}$
- возведение в степень это повторённое умножение: $x^n = \underbrace{x \cdot x \cdot \ldots \cdot x}_{n}$
- тетрация это повторённое возведение в степень:

$$^{n}x = \underbrace{x^{x^{\cdot^{\cdot^{x}}}}}_{n}$$

**Степенная башня вычисляется сверху вниз.** Это принципиально:

$$^{4}2 = 2^{2^{2^{2}}} = 2^{2^{4}} = 2^{16} = 65536$$

Если считать снизу вверх, получится $((2^2)^2)^2 = 256$, другой и неправильный ответ.

Напишите **рекурсивную** функцию. База рекурсии: $^{0}x = 1$ для любого `x`.

```python
tetration(2, 0)   # 1
tetration(2, 1)   # 2
tetration(2, 2)   # 4
tetration(2, 3)   # 16
tetration(2, 4)   # 65536
tetration(3, 2)   # 27
tetration(5, 2)   # 3125
```

**Вопрос со звёздочкой:** из скольких цифр состоят числа $^{3}5$ и $^{5}2$? Ответьте на него в блоке `if __name__ == "__main__":`.

Числа получатся такими большими, что Python откажется превращать их в строку - он защищается от случайного зависания. Снимите ограничение:

```python
import sys
sys.set_int_max_str_digits(100000)
```

> Не пробуйте `tetration(2, 6)`. Это $2^{65536}$ в показателе степени - число, у которого больше цифр, чем атомов во Вселенной. Сначала оцените размер, потом запускайте: ровно тот навык, ради которого была третья часть конспекта.

## 9. Степень делителя факториала - ⭐⭐⭐⭐ - 20 баллов



> **Файл:** `legendre.py` | **Функция:** `max_power(n, k)`

Даны числа $n$ и $k$. Найдите наибольшую степень $x$ такую, что $n!$ делится на $k^x$.

### Случай простого $k$

Начнём с простого $k$. Распишем факториал:

$$n! = 1 \cdot 2 \cdot 3 \cdot \ldots \cdot (n-1) \cdot n$$

Каждый $k$-й сомножитель делится на $k$ и добавляет $+1$ к ответу. Таких сомножителей $\left\lfloor \dfrac{n}{k} \right\rfloor$.

Далее, каждый $k^2$-й сомножитель делится на $k^2$ и добавляет **ещё** $+1$, ведь первую степень мы уже посчитали в предыдущем абзаце. Таких сомножителей $\left\lfloor \dfrac{n}{k^2} \right\rfloor$.

И так далее. Итого:

$$\left\lfloor \frac{n}{k} \right\rfloor + \left\lfloor \frac{n}{k^2} \right\rfloor + \left\lfloor \frac{n}{k^3} \right\rfloor + \ldots$$

Это [формула Лежандра](https://en.wikipedia.org/wiki/Legendre%27s_formula). Сумма конечна: слагаемые обнуляются, как только $k^i > n$, то есть примерно после $\log_k n$ шагов.

**Пример.** Пусть $n = 10$, $k = 2$:

$$\left\lfloor \frac{10}{2} \right\rfloor + \left\lfloor \frac{10}{4} \right\rfloor + \left\lfloor \frac{10}{8} \right\rfloor = 5 + 2 + 1 = 8$$

Значит, $10!$ делится на $2^8$, но не на $2^9$.

### Случай составного $k$

А вот здесь начинается настоящая задача. Для составного $k$ формула Лежандра напрямую не работает.

Разложите $k$ на простые множители: $k = p_1^{e_1} \cdot p_2^{e_2} \cdot \ldots$ Чтобы $n!$ делилось на $k^x$, нужно, чтобы в $n!$ хватило **каждого** простого множителя. По каждому $p_i$ считаем, сколько раз он входит в $n!$ по формуле Лежандра, делим нацело на $e_i$ и берём **минимум** по всем множителям: узкое место определяет ответ.

```python
max_power(10, 2)     # 8
max_power(10, 3)     # 4
max_power(10, 5)     # 2
max_power(5, 2)      # 3
max_power(10, 10)    # 2
max_power(25, 6)     # 10
max_power(100, 12)   # 48
max_power(1000, 7)   # 164
```

Проверьте `max_power(10, 10)` руками: $10 = 2 \cdot 5$, двоек в $10!$ восемь, пятёрок две, минимум равен двум. И правда, $10! = 3\,628\,800$ оканчивается ровно на два нуля.

> Вычислять сам факториал **нельзя**: при $n = 10^9$ он не поместится ни в какую память. Вся суть формулы Лежандра в том, что ответ считается за $\log n$ шагов. Тест это проверяет.

## 10. Пути на координатной плоскости - ⭐⭐⭐⭐⭐ - 25 баллов



> **Файл:** `lattice_paths.py` | **Функция:** `count_paths(n, k)`

Иван изучает комбинаторику и ищет количество способов построить путь из точки $(a, b)$ в точку $(c, d)$ на координатной плоскости. Двигаться можно только по горизонтали и вертикали, посещать одну точку дважды нельзя. То есть путь состоит ровно из $|a-c| + |b-d|$ шагов.

Даны два множества точек:

- множество $A$: точки с координатой $X = 0$ и $Y$ от $1$ до $N$ включительно;
- множество $B$: точки с координатой $X = K$ и $Y$ от $1$ до $N$ включительно.

Найдите сумму количеств путей от каждой точки $A$ до каждой точки $B$. Ответ выведите по модулю $10^9 + 7$.

```python
count_paths(2, 2)   # 8
count_paths(4, 5)   # 236
```

**Разбор примера.** Для $N = 2$, $K = 2$ есть четыре пары точек:

```text
Путей [(0,1) -> (2,1)] = 1
Путей [(0,2) -> (2,2)] = 1
Путей [(0,1) -> (2,2)] = 3
Путей [(0,2) -> (2,1)] = 3
```

Итого 8.

**Ключевая идея.** Путь длины $|a-c| + |b-d|$ без повторного посещения точек является **монотонным**: каждый шаг приближает нас к цели. Значит, путь полностью описывается тем, **в каком порядке** мы делаем шаги по горизонтали и по вертикали.

Пусть нужно сделать $dx$ шагов по горизонтали и $dy$ по вертикали. Всего шагов $dx + dy$, и надо выбрать, какие из них будут горизонтальными:

$$\binom{dx + dy}{dx}$$

Проверьте на примере: из $(0,1)$ в $(2,2)$ нужно $dx = 2$, $dy = 1$, значит $\binom{3}{2} = 3$. Сошлось.

**Дальше про эффективность.** Наивное решение перебирает все $N^2$ пар точек. При $N = 10^6$ это триллион операций, что неприемлемо. Подумайте:

1. Сколько существует **различных** значений $dy = |i - j|$?
2. Сколько пар $(i, j)$ дают каждое конкретное значение $dy$?
