## Как оформлять решения

Для каждой задачи указаны **имя файла** и **сигнатура функции**. Соблюдайте их буквально, по ним работает автоматическая проверка.

- Функция **возвращает** результат через `return`, а не печатает его.
- Печать для демонстрации - в блоке `if __name__ == "__main__":`.
- Один файл - одна задача.

Решения кладите в папку `solutions` в корне репозитория, тесты лежат в папке `tests` там же. Проверить себя:


## 1. Стиль Джейдена Смита - ⭐ - 5 баллов



> **Файл:** `jaden.py` | **Функция:** `to_jaden_case(text)`

Джейден Смит пишет твиты, начиная каждое слово с заглавной буквы. Воспроизведите этот стиль.

На входе обычная строка:

```
"How can mirrors be real if our eyes aren't real"
```

На выходе:

```
"How Can Mirrors Be Real If Our Eyes Aren't Real"
```

Первая буква каждого слова стала заглавной, все остальные - строчными.

Обратите внимание на слово `"aren't"`.

- Наивный алгоритм мог бы сделать `"Aren'T"`, потому что увидел бы букву `t` после апострофа и тоже захотел бы сделать её заглавной.
- Правильный результат - `"Aren't"`: слово - это то, что разделено пробелами, апостроф внутри слова ничего не разделяет.

```python
to_jaden_case("most trees are blue")
# 'Most Trees Are Blue'

to_jaden_case("When I die. then you will realize")
# 'When I Die. Then You Will Realize'

to_jaden_case("Dying is mainstream")
# 'Dying Is Mainstream'
```

## 2. Сумма чисел в интервале - ⭐ - 5 баллов



> **Файл:** `sum_interval.py` | **Функции:** `sum_interval(a, b)`

Для двух целых чисел `a` и `b` найдите сумму всех целых чисел между ними, включая границы. Числа могут быть отрицательными и приходить в любом порядке; если они равны, верните само это число.

```python
sum_interval(1, 0)    # 1    1 + 0
sum_interval(1, 2)    # 3    1 + 2
sum_interval(-1, 2)   # 2    -1 + 0 + 1 + 2
sum_interval(5, 5)    # 5
```

> **Проверьте себя:** решение циклом очевидно. А теперь примените формулу Гаусса и обойдитесь без цикла - для границ порядка миллиарда это единственный работающий способ.

## 3. Степень двойки - ⭐ - 5 баллов



> **Файл:** `power_of_two.py` | **Функция:** `is_power_of_two(n)`

Неотрицательное целое `n` является степенью двойки, если найдётся такое целое `k`, что $n = 2^k$. Верните `True` или `False`.

```python
is_power_of_two(1)      # True    2^0
is_power_of_two(1024)   # True
is_power_of_two(4096)   # True
is_power_of_two(333)    # False
is_power_of_two(0)      # False
```

> **Проверьте себя:** посмотрите на двоичную запись степени двойки - в ней ровно одна единица. Отсюда следует решение в одну строку без единого деления.

## 4. Вес двух команд - ⭐ - 5 баллов



> **Файл:** `teams.py` | **Функция:** `team_weights(weights)`

## 5. Квадраты цифр - ⭐⭐ - 10 баллов



> **Файл:** `square_digits.py` | **Функция:** `square_digits(n)`

![Разбор числа 9119](images/square-digits.svg#only-light)
![Разбор числа 9119](images/square-digits.dark.svg#only-dark)

На входе целое неотрицательное число. Например, `9119`. Нужно:

1. Разобрать его на отдельные цифры: `9`, `1`, `1`, `9`.
2. Каждую цифру возвести в квадрат: $9^2 = 81$, $1^2 = 1$, $1^2 = 1$, $9^2 = 81$.
3. Получившиеся результаты **склеить** в одно новое число: `81` + `1` + `1` + `81` = `811181`.

Из `9119` получился `811181`.


```python
square_digits(3212)   # 9414
square_digits(2112)   # 4114
square_digits(0)      # 0
square_digits(999)    # 818181
square_digits(10001)  # 10001
```

## 6. Числа Дисариума - ⭐⭐ - 10 баллов



> **Файл:** `disarium.py` | **Функция:** `is_disarium(n)`

Число Дисариума равно сумме своих цифр, возведённых в степень, равную позиции цифры (позиции считаются слева направо, начиная с единицы).

```python
is_disarium(89)    # True    8^1 + 9^2 = 8 + 81 = 89
is_disarium(135)   # True    1^1 + 3^2 + 5^3 = 1 + 9 + 125 = 135
is_disarium(564)   # False   5^1 + 6^2 + 4^3 = 105
```

## 7. Сумма чётных чисел Фибоначчи - ⭐⭐⭐ - 15 баллов



> **Файл:** `even_fib_sum.py` | **Функция:** `even_fib_sum(limit)`

Последовательность Фибоначчи задана так:

$$F_1 = 1, \quad F_2 = 2, \quad F_n = F_{n-1} + F_{n-2}$$

то есть `1, 2, 3, 5, 8, 13, 21, 34, ...`

Нужно:

1. Сгенерировать все числа Фибоначчи, которые **не превышают** `limit`;
2. выбрать из них только **чётные**;
3. найти **сумму** этих чётных чисел.

```python
even_fib_sum(13)        # 10        (2 + 8)
even_fib_sum(34)        # 44        (2 + 8 + 34)
even_fib_sum(100)       # 44
even_fib_sum(200)       # 188
even_fib_sum(10000)     # 3382
even_fib_sum(4000000)   # 4613732
```

## 8. Устойчивость числа - ⭐⭐⭐ - 15 баллов



> **Файл:** `persistence.py` | **Функция:** `persistence(num)`

Мультипликативная устойчивость числа - это количество шагов, за которое число превращается в однозначное, если на каждом шаге перемножать его цифры.

```python
persistence(39)   # 3    3*9=27 -> 2*7=14 -> 1*4=4
persistence(999)  # 4    729 -> 126 -> 12 -> 2
persistence(25)   # 2    10 -> 0
persistence(4)    # 0    число уже однозначное
```

> **Проверьте себя:** найдите число с устойчивостью 5 перебором до миллиона. Оно существует, и его поиск - хорошая проверка того, что цикл написан правильно.

## 9. Черепашьи бега - ⭐⭐⭐⭐ - 20 баллов



> **Файл:** `tortoise_racing.py` | **Функция:** `race(v1, v2, g)`

![Относительная скорость черепах](images/tortoise.svg#only-light)
![Относительная скорость черепах](images/tortoise.dark.svg#only-dark)

У нас есть две черепахи:

- **Черепаха A** (ленивая): ползёт со скоростью `v1` футов в час. У неё фора в `g` футов.

**Через какое время B догонит A?**

```python
race(720, 850, 70)    # [0, 32, 18]

race(80, 100, 40)     # [2, 0, 0]
race(720, 850, 370)   # [2, 50, 46]
race(820, 850, 550)   # [18, 20, 0]
race(100, 100, 50)    # None
```

## 10. Числа словами - ⭐⭐⭐⭐⭐ - 25 баллов



> **Файл:** `words_to_number.py` | **Функция:** `words_to_number(text)`

У нас есть строки - английские слова, которыми люди записывают числа, - и нужно превратить их обратно в обычные цифры.

```python
words_to_number("one")                # 1
words_to_number("twenty")             # 20
words_to_number("two hundred forty-six")   # 246
words_to_number("seven hundred eighty-three thousand nine hundred and nineteen")
# 783919
```

**Несколько важных заметок на полях:**

1. Самое маленькое число - `"zero"`. Ноль тоже считается.
2. Самое большое - `"one million"`. Больше миллиона приносить не нужно, наш парсер ещё не вырос.
3. Словечко `"and"` капризное: иногда оно есть, иногда его нет. Наш алгоритм должен быть достаточно ловким, чтобы просто его игнорировать.
4. Все входные строки корректны. Не нужно тратить силы на проверку, что "двадцать пятьдесят" - это ерунда.

Представьте, что слова `"hundred"`, `"thousand"`, `"million"` - это математические операторы вроде `+` и `*`. Они умножают всё, что было до них, на свой коэффициент.

`"two hundred"` - это $2 \times 100$. `"forty-six"` - это $40 + 6$.

А теперь разберём сложный пример по частям:

`"seven hundred eighty-three thousand nine hundred and nineteen"`

1. **"seven hundred"**: видим оператор `hundred` $\to$ $7 \times 100 = 700$
2. **"eighty-three"**: просто число, прибавим позже $\to$ $80 + 3 = 83$
3. **"thousand"** - это наш *большой* оператор. Он значит: "всё, что я набрал до этого момента, нужно умножить на 1000 и отложить в большую копилку". Итого: $(700 + 83) \times 1000 = 783\,000$
4. Дальше пошли разряды поменьше. **"nine hundred"** $\to$ $9 \times 100 = 900$
5. И наконец, **"nineteen"** $\to$ $19$
6. Складываем всё: $783\,000 + 900 + 19 = 783\,919$

Обратите внимание: нужны **две копилки** - одна для текущей группы (до ближайшего большого оператора) и одна для итога. Дефис внутри `"forty-six"` - такой же разделитель, как пробел.
